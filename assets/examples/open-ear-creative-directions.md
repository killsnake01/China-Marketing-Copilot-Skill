# 黄金样例：开放式耳机小红书创意

## 原始输入

```text
给我三个适合小红书的开放式耳机种草创意，每个带风险提示。只做创意，不要完整方案。
```

## 任务路由

- 主路由：`docs/routes/creative-campaign.md`
- 品类索引：`knowledge-base/headphones/_index.md`
- 风险参考：`docs/ecosystem/negative-early-warning.md`

## 最终输出片段

```markdown
开放式耳机小红书创意

先给结论：优先做“漏音尴尬自测”，场景具体、评论区有参与感，也最容易暴露产品边界。

### 创意1：地铁漏音尴尬自测
- 钩子：开放式耳机坐地铁，旁边的人到底听不听得到？
- 展开：用安静办公室、地铁站台、行驶车厢三个场景，记录相同音量下旁人的实际反馈。
- 证据要求：补统一音量、距离、环境噪声和实拍原声；结果当前为 `[待验证]`。
- 评论区预判：“这不就是外放？”“音量开小当然听不到。”
- 风险提示：结果不稳定时缩窄到办公室场景，避免承诺零漏音。

### 创意2：耳朵几点开始想下班
- 钩子：不测“全天无感”，只记录第30、60、120分钟耳朵想摘下来的时刻。
- 展开：邀请不同耳形用户记录夹耳、压耳、滑落和眼镜冲突。
- 证据要求：公开样本人数、佩戴时长和眼镜情况；舒适度属于主观体验。
- 评论区预判：“换个人就不一样。”“戴眼镜再试试。”
- 风险提示：不能把少量体验写成所有人都舒适。

### 创意3：通勤时我需要听见什么
- 钩子：播客继续听，报站、车铃和同事叫你也别错过。
- 展开：用步行、办公室和候车三个低风险场景展示环境感知，再补通话切换。
- 证据要求：环境声可听程度和通话效果均需实测，避免用安全承诺替代测试。
- 评论区预判：“风噪怎么办？”“嘈杂环境还能听清吗？”
- 风险提示：骑行等高风险场景不做安全保证，风噪能力标记 `[待验证]`。

自检: 0个数值已核 | 0个产品已核 | 0个来源已标注 | 置信度:低
```

## 关键判断依据

- 开放式耳机的高频争议集中在漏音、佩戴和风噪，创意要主动把边界放进内容。
- 小红书创意需要可参与、可复现的场景，避免先写抽象卖点。
- 未提供具体产品和测试结果时，证据要求优先于效果承诺。

## 预期断言

- 必含三个完整创意，每个都有钩子、证据要求、评论区预判和风险提示。
- 必须先给推荐创意，再展开三个方向。
- 不能增加上市决策包、管理层纪要、路线评分卡或72小时动作。
- 不能把漏音、舒适度、风噪或安全表现写成已验证事实。
